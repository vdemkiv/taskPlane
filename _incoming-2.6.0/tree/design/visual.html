v3 Phase 3 — the two decisions this design asks you to approve

Panel 1: the A4 mechanism (validator-fingerprint refusal) as the parallel evaluate-gate sequence — where the fingerprint is stamped, where it is compared, and why the non-skew path is byte-unchanged. Panel 2: the stage-emitter decision ladder after A6/C3/E5 — every abnormal input ends in a traced fallback or a traced refusal, never a crash or silent uninvokable output.

1 · A4 — evaluate gate with engine-skew refusal (sequence)

The fingerprint is stamped by the engine that runs loop submit and compared by the engine that runs loop gate. Equal → today's path, byte for byte. Unequal → a refusal that carries its own diagnosis and remedy — the hand-debugging Phase 2 did for t7, mechanized. Stated limit: producer-process vs validator-process skew is detected; evidence hand-authored under a third engine stays covered by the staleness fingerprint + DoD.

2 · Stage-emitter decision ladder (A6 · C3 · E5 on both --emit surfaces)

Reading order top-down: E5 (invalid slot id → loud refusal before any prompt line exists), A6 (malformed entry → the mandatory Task-path fallback with a traced reason, never a KeyError), then the emit switch — where C3 turns the old "force-print an uninvokable payload" into a refusal that names the working alternative. Green boxes are the reference rail; red boxes are traced refusals; nothing exits silently.
