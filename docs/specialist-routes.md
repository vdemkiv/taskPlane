# Specialist routes

Use the user's requested outcome and existing decisions to select useful Product,
Design, implementation, evaluation or Engineering work. A strategic note is
advisory, a review does not implement, and standalone scope remains standalone.

Root integrated work, serial ownership and useful scoped native specialists are
valid. No phase requires a specialist count or separate worker per lens. Explicit
requested native independence remains binding. Choose disjoint tasks when useful,
with concrete purpose, relevant inputs, exact paths and actual prerequisites.

A worker returns artifacts, findings/check outcomes, limitations and actual native
identity/completion evidence. It cannot widen scope, approve phases or start a
nested run. Root accepts fresh joined results before dependent work and separately
presents each phase for human approval. Unknown completion/cancellation retains
uncertain ownership. See [native ownership](../skills/tp-go/references/codex-native-dispatch.md).

Use a durable brief and ordinary references rather than replaying predecessor
chat or collecting context/startup receipts. Graph/dashboard/telemetry are optional.
Preserve failed/unknown verification and distinguish local fixtures from live host
acceptance.
