# Author and invoke workflows

Preserve create/edit/inspect/preview/run/create-and-run intent. Consult
[Workflow Builder](../../docs/workflow-builder.md) and the actual runtime's
`workflow catalog`. Catalog, inspect, validate and preview are read-only; they do
not activate a run. Preview binds typed inputs and reports unresolved values,
reads, writes, dependencies and runtime blockers, without executing tasks.

Author during a scoped Design visit. Reuse accepted decisions and compatible
active work; never nest or silently replace a run. Choose registered capabilities,
necessary inputs, stable criteria and exact current output paths. Future delivery
Build scope is finalized in Plan. Saving alone never executes. Publish a changed
definition as a new semantic version; preserve prior published bytes and pinned
active invocations. Treat definition strings as data, not executable authority.

Present the definition, effects, validation and useful preview for Design
approval. Create-only ends there. An existing create-and-run request permits the
root handoff after authoring acceptance and route completion, not unseen phase
approvals. Compile to a fresh bootstrap/output prefix, inspect the pinned package
and use its actual start arguments through existing `flow` controls.

Follow [the shared flow](../tp-go/references/shared-flow.md). New runs use
`brief/v1` and `ownership/v1`; native work is proportionate unless an explicit
independence obligation is declared. Join actual workers before accepting results.
Standalone routes remain standalone; full delivery retains seven approvals.
Changed relevant pinned inputs require revalidation. Saving or changing a draft
cannot retarget a running invocation, and fixtures cannot certify a live host.
