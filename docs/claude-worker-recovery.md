# Claude native worker evidence and recovery

Inspect the actual loaded runtime, owning run and exact worker attempt. Preserve
native Agent/Task call identity, pinned child, original handback/terminal records,
relevant source/prerequisite inputs and known command handles. A missing report,
Stop label, output file, mailbox message or cancellation request is not proof of
completion. Do not release uncertain ownership or synthesize a replacement event.

Ordinary one-use CLI invocation transport may bind the observed native principal.
It is not a freely supplied grant/environment identity and is distinct from the
removed startup-only transport. New runs have no startup account, source probe,
context receipt, byte/timing fence or first-worker readiness cohort.

For interrupted work, use current supported status/recovery controls for the
actual observed condition. Retain original evidence and failed attempts; do not
substitute another recovery operation merely because one refused. Retry only
after a relevant changed condition and fresh correlated attempt. Actual transcript
and hook flush orders must converge without inventing a human/worker event.

Stop requests record cancellation intent. Only authoritative native terminal
observations plus terminal known commands can establish completion. Root verifies
relevant freshness and accepts returned artifacts separately from phase approval.
Explicit independence obligations remain incomplete when native capability is
unavailable; root work cannot be relabeled independent native evidence.

Disposable local fixtures are not live acceptance. Candidate installation/reload,
interactive restart, bridge behavior, Windows launcher and live process exit need
separate actual observations. Historical scripts/reports may describe removed
protocols; inspect the loaded candidate's help before using instrumentation and
never weaken permissions or overwrite installed caches to obtain a pass.
