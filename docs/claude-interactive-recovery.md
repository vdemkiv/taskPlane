# Claude interactive recovery

This candidate preserves native identity and permission evidence during recovery. A launch failure, startup report, stop observation, terminal notification and accepted result are separate facts. A missing report does not prove that a child stopped.

Inspect the current run and the exact attempt before recovery. Match the parent, child, admission, native call/result, cycle ordinal, original or resumed cycle and loaded runtime. Preserve original transcripts and their hashes. Read the complete relevant histories through the resumable native reader; a partial cursor is incomplete evidence and cannot release a reservation. Later native activity, changed prefixes, duplicate identities or unsupported safe file reading must refuse without changing ownership.

Use the runtime's supported recovery operation for the observed condition: unavailable worker, unbound terminal launch, launch denial, handback reconciliation or startup reconciliation. These operations have different proof requirements; never substitute one because another refused. `flow worker --operation startup-status` reports the current state. A supported `stop` request records a stop fence but does not establish process exit or accept a result. Do not remove reservations, edit the controller or manufacture hooks.

The shipped `scripts/verify_claude_interactive.py` exposes prepare, launch, resume and inspect modes. Inspect its current help and prepare a separately authorized disposable journey before launching. Record actual native versions, candidate hashes and original/resumed identities. Fixtures and immediate script success do not certify a real interactive session. A denied native permission remains a denial; retry requires its own valid authorization and fresh attempt.

Candidate status: functional native recovery and installed interactive restart evidence must be verified on the final candidate. This document makes no claim that those external journeys have already passed.
