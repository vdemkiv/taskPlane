# Host-native workflow surfaces

Codex and Claude share one workflow contract, durable brief, scoped ownership and
seven separate human approvals. The actual loaded runtime and host adapter matter;
a version label, edited checkout or package archive does not prove loaded hooks.

Present concrete results in the conversation with useful artifact links. Dashboard,
graph, browser, side panel and inline visuals are optional projections. Their
absence, queued open or telemetry failure does not veto a result. UI success
never authenticates approval or proves a native process completed.

Interpret ordinary human intent with observed actor/conversation, full response,
time/reference and unchanged current target. Preserve chronology/replay checks.
This is cooperative observation, not independent human authentication. Explicit
different targets or unclear conditional responses stay pending. There is no
presentation grammar, exact phrase or required dashboard display.

Root/serial work and useful native workers are valid. Retain actual launch/child
identity and terminal observations for delegated work on each host, including
Claude transcript/hook flush order. Report unavailable capabilities and missing
measurements honestly. Host permissions remain in force; Taskplane does not create
an OS sandbox or complete opaque-shell containment. See
[native ownership](../skills/tp-go/references/codex-native-dispatch.md).
