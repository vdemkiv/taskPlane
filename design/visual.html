R-0006: gates before dependence

The five waves form a one-way quality sequence. Behavior remains reversible within a wave, but each protective gate stays in place for later work. Every lens run in these waves is quick-only; a substantive finding returns to correction and never promotes to a deep worker.

Wave 1

Fresh baseline

entry authority
  • Fresh run and current SHA
  • Refreshed source graph
  • Prior Git/knowledge fingerprints preserved
  • Quick-only dispatch policy
Wave 2

Python compatibility

before mutation/tests
  • Fix PEP-701-only f-string
  • Eager named compatibility refusal
  • CPython 3.10–3.13
  • Compile/import before pytest
Wave 3

Visible truth

before pushed-green
  • Structured graph degradation
  • Known CLI error envelopes
  • Zero-token corpus in CI
  • Exact remote SHA proof
Wave 4

Cycle ratchet, then cuts

commit 4A → commit 4B
  • Measure full SCC inventory
  • Reject growth/new members
  • Add acyclic graph primitives
  • Remove S1/S2 imports
Wave 5

Evaluation confidence

bounded claim only
  • 1–100 distinct trials
  • Three incomplete-work fixtures
  • Selective eval graph edges
  • Seeded-failure catch-rate

Cross-wave invariants

  • No governed-state mutation before compatibility refusal.
  • No strict gate accepts degraded graph evidence.
  • No cycle cut lands before the ratchet commit.
  • No incomplete sample or zero sample becomes a success rate.
  • No quick finding creates a deep slot.

Separate wave 6

Package moves, component/schema redesign, workspace and plugin identity, model-tier policy, attestation, MCP, physical isolation, and broader architecture/security bets remain outside this graph.

They require a separate requirement and human-approved Design Contract.
