# State import and candidate release

Recovery preserves authentic provenance and durable history. Inventory the exact
original controller, retained request/approval observation, workspace/root identity
and referenced evidence. Inspection or `ready_to_import` is not continuation
authority. Use supported import controls; preserve original bytes and incomplete
transaction records. Never fabricate a marker or replace a different store.

Inactive inventory accepts exactly one authentic ordinary initialization or
verified committed import provenance. Bind/relocate only inactive/retired stores,
validate archive/history and refuse active, pending, missing, ambiguous or tampered
state. A fresh store inherits no approvals/native authority. Back up the complete
quiescent state and referenced artifacts, not a lone controller JSON.

Package producers select regular in-root members and record source/dirty lineage,
archive and member digests. Verify both extracted host archives against tested
candidate bytes at this meaningful boundary. A commit/version label alone does
not prove source identity, and local package success does not establish live hooks,
interactive restart, platform CI, actual power loss or publication readiness.

Installation/reload and publication are separate actions. Preserve existing
runtime/history and use supported host controls between runs. The candidate reads
old-contract history and refuses its active mutation; do not silently migrate it
or copy old decisions into a new run. Installed caches remain unchanged by package
build. Keep actual live capability gaps visible with owners and evidence.
